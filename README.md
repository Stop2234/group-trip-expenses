# Расходы группы после поездки

Веб-приложение для учёта совместных расходов поездки с **MCP-сервером**:
через разговор с AI-агентом можно добавлять расходы, читать список расходов
и рассчитывать взаиморасчёты. **Веб-интерфейс и агент работают с одними данными**,
а денежные расчёты выполняет код приложения (целые копейки).

## Возможности

- управление участниками поездки;
- добавление, редактирование и удаление расходов;
- равное и неравное (по долям) распределение расходов;
- расчёт фактически оплаченной суммы, доли и итогового баланса каждого участника;
- формирование переводов для закрытия долгов;
- демо-набор данных;
- валидация пользовательского ввода;
- интерфейс на русском языке;
- MCP-сервер для управления расходами через агента (OpenCode и любой MCP-клиент).

## Стек

- **Frontend:** React 18, TypeScript, Vite;
- **Backend:** Node.js, Express 5 (REST API + MCP endpoint);
- **MCP:** официальный `@modelcontextprotocol/sdk` (Streamable HTTP, stateless);
- **Хранение:** единый JSON-файл (`data/trip-data.json`);
- **Тесты:** Vitest (81 тест), интеграционные тесты с реальным MCP-клиентом SDK.

## Архитектура

```
React UI ──HTTP──► REST API (/api/*)  ─┐
                                       ├──► ExpenseService ──► JSON-хранилище
MCP-агент ──MCP──► MCP tools (/mcp)  ──┘        (data/trip-data.json)
```

- **`src/lib/`** — общий доменный слой (`types`, `money`, `calc`, `validation`,
  `service`, `demo`). Используется и frontend, и backend. Денежная логика
  (`calc.ts`, `money.ts`) единая: MCP-инструменты НЕ реализуют собственных
  расчётов, они вызывают `ExpenseService`.
- **`server/`** — backend: `JsonFileStorage` (единое хранилище), REST API
  (`api.ts`), MCP-инструменты (`mcp.ts`), точка входа (`index.ts`).
- **`src/`** — React UI, читает/пишет данные только через REST API.

Хранилище одно: JSON-файл с атомарной записью. Других копий состояния нет,
localStorage не используется.

## Хранение данных

Единый файл `data/trip-data.json` (путь переопределяется переменной
окружения `DATA_FILE`). Файл создаётся автоматически при первом сохранении.
Повреждённый файл не роняет приложение: он переименовывается в
`*.corrupt-<timestamp>`, начинается пустое состояние.

## Установка и запуск

```bash
npm install
npm run dev
```

`npm run dev` поднимает backend (порт 3001) и Vite dev-сервер (порт 5173).
Приложение: **http://localhost:5173** (Vite проксирует `/api` и `/mcp` на backend).

Раздельный запуск:

```bash
npm run dev:server   # backend: http://127.0.0.1:3001
npm run dev:web      # frontend: http://localhost:5173
```

Production:

```bash
npm run build        # tsc + vite build → dist/
npm start            # backend на http://127.0.0.1:3001 (отдаёт dist/ и API)
```

Переменные окружения backend:

- `PORT` — порт (по умолчанию 3001);
- `DATA_FILE` — путь к файлу данных (по умолчанию `data/trip-data.json`).

## REST API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/state` | Полное состояние (участники + расходы) |
| GET | `/api/summary` | Сводка: балансы, переводы, суммы |
| GET | `/api/settlements` | Взаиморасчёты |
| GET | `/api/participants` | Участники |
| POST | `/api/participants` | Добавить участника `{ "name": "Имя" }` |
| DELETE | `/api/participants/:id` | Удалить участника |
| GET | `/api/expenses` | Расходы |
| POST | `/api/expenses` | Добавить расход `{ "title", "amountRubles", "paidBy", "participants", "splitMode?", "customSharesRubles?" }` |
| PUT | `/api/expenses/:id` | Обновить расход |
| DELETE | `/api/expenses/:id` | Удалить расход |
| POST | `/api/demo` | Загрузить демо-данные |
| DELETE | `/api/trip` | Очистить поездку |

Ошибки: `400` — валидация, `404` — не найден участник/расход,
`409` — небезопасное удаление. Тело: `{ "error": { "code", "message" } }`.

## Подключение MCP

### 1. Запустите backend

```bash
npm run dev:server
```

MCP endpoint: **`http://127.0.0.1:3001/mcp`** (Streamable HTTP, stateless,
без API-ключей и OAuth).

### 2. Добавьте сервер в OpenCode

В `opencode.json` (или через `opencode mcp add`):

```json
{
  "mcp": {
    "servers": {
      "trip-expenses": {
        "type": "remote",
        "url": "http://127.0.0.1:3001/mcp"
      }
    }
  }
}
```

Порядок: сначала `npm run dev:server`, затем открыть OpenCode-сессию.
Проверка: `opencode mcp list` должен показать `trip-expenses`.

## MCP-инструменты

| Инструмент | Назначение |
|---|---|
| `add_expense` | Добавить расход (сумма в рублях, плательщик и участники по именам/ID) |
| `list_expenses` | Список расходов из общего хранилища |
| `calculate_settlements` | Балансы и переводы (рассчитывает код приложения) |
| `list_participants` | Список участников |
| `add_participant` | Добавить участника |
| `remove_expense` | Удалить расход по ID |
| `load_demo` | Загрузить демо-данные в общее хранилище |
| `get_summary` | Итоговая статистика поездки |

### Примеры естественных запросов агенту

- «Добавь ужин на 3000 рублей, платил Егор, делили на троих: Егор, Анна, Иван»;
- «Покажи все расходы»;
- «Кто кому сколько должен после поездки?»;
- «Сувениры за 2750 заплатила Мария, но Егору досталось на 1000, Анне на 750,
  остальное Ивану и Марии поровну» (неравное распределение);
- «Загрузи демо-данные».

**Неоднозначные запросы.** Схема `add_expense` делает поле `participants`
обязательным, а описание требует от агента: если из запроса нельзя однозначно
определить участников распределения или способ деления — сначала уточнить у
пользователя и НЕ вызывать инструмент с придуманными значениями.
Вызов без `participants` отклоняется схемой до записи.

**Ошибки.** Инструменты возвращают структурированную ошибку
(`PAYER_NOT_FOUND`, `INVALID_AMOUNT`, `SHARES_MISMATCH` и др.) без stack trace;
данные не повреждаются.

## Демо-данные

Кнопка «Загрузить демо-данные» в интерфейсе или `POST /api/demo`,
либо MCP-инструмент `load_demo`. Набор: 4 участника, 5 расходов, разные
плательщики, расход между частью участников, пример неравного распределения.

## Проверка общих данных web ↔ MCP

Автоматизировано в `tests/shared-storage.test.ts` и
`tests/mcp-integration.test.ts` (реальный MCP-клиент SDK):

- расход, добавленный через MCP, виден через `GET /api/expenses` (тот же ID);
- расход, добавленный через `POST /api/expenses`, виден через
  `tools/call list_expenses`;
- расчёт взаиморасчётов через MCP использует данные, добавленные через HTTP;
- демо-данные через MCP видны веб-интерфейсу.

Реальный журнал вызовов: `artifacts/demo_chat.jsonl` и `artifacts/demo_chat.md`.

## Ограничения

- данные хранятся только локально в JSON-файле, синхронизации между
  устройствами нет;
- одна валюта — рубли (копейки поддерживаются);
- экспорт/импорт JSON или CSV не реализован;
- MCP endpoint stateless: сессии между запросами не сохраняются;
- backend слушает только 127.0.0.1 (локальный запуск).
