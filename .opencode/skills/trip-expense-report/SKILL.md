# trip-expense-report — итоговый отчёт по поездке

## Что это за скилл

Скилл берёт реальные данные поездки из приложения расходов, проверяет суммы,
доли, балансы и переводы независимым пересчётом и собирает из них Markdown-отчёт
по стайлгайду `STYLE_GUIDE.md`.

Скилл работает с любой поездкой: он не знает конкретных участников и сумм. В нём
нет имён, названий расходов и цифр из примеров — только порядок действий и
требования к отчёту.

## Когда применять

- просят итоговый отчёт по поездке («собери отчёт», «итоговые расходы»,
  «сколько каждый должен после поездки»);
- просят проверить расчёты и сохранить результат в Markdown;
- просят отчёт по конкретному источнику данных (другой сервер, другой файл).

## Когда НЕ применять

- просят **добавить, изменить или удалить** расход/участника — это делает само
  приложение (REST API или MCP-инструменты `add_expense`, `remove_expense`,
  `add_participant`), скилл тут не участвует;
- просят **перевести деньги** или «закрыть долг» — скилл только рекомендует
  переводы в отчёте, сам ничего не переводит;
- вопрос не про отчёт по расходам (погода, код, другая тема) — отвечать
  обычным порядком, скилл не поднимать;
- данных нет или их не хватает для честного расчёта — не выдумывать, а остановиться
  (см. «Если данных не хватает»).

## Что нужно на входе

1. **Источник данных** — один из трёх вариантов:
   - MCP-сервер приложения (`trip-expenses`), если он подключён к клиенту;
   - REST API (`GET /api/state`, `GET /api/settlements`) по адресу вида
     `http://127.0.0.1:3001` (порт может быть другим — спроси или посмотри в
     логе запуска сервера);
   - файл данных JSON (по умолчанию `data/trip-data.json`, путь задаётся
     переменной окружения `DATA_FILE`).
2. **Куда сохранить отчёт** — путь к файлу `.md`. Если не назван, спроси или
   используй `reports/report-<дата>.md`.

Если источник не задан — не гадай: спроси, какой источник читать.

## Порядок работы

1. **Определи источник.** Сначала попробуй MCP: инструменты
   `list_participants`, `list_expenses`, `calculate_settlements` (они есть не
   всегда). Если MCP-инструментов нет — REST: `GET /api/state` и
   `GET /api/settlements`. Если сервера нет — файл данных. Какой путь использовал,
   обязательно запиши в отчёт в строку `**Источник данных:**`.
2. **Получи данные.** Нужны: участники (id и имена), расходы (id, название,
   сумма в копейках, плательщик, участники, способ распределения, доли),
   балансы и переводы. Расчёты бери из приложения (`calculate_settlements` /
   `GET /api/settlements`), не придумывай их сам.
3. **Проверь полноту данных** (см. «Если данных не хватает»): есть ли участники,
   есть ли расходы, целые ли копейки, существуют ли плательщик и участники
   расходов.
4. **Сопоставь четыре вещи между собой:** суммы расходов, доли участников,
   балансы и переводы.
5. **Сделай независимую контрольную проверку** в целых копейках (не пользуясь
   готовыми числами из отчёта): сумма всех расходов, доли каждого расхода,
   баланс каждого участника, закрытие долгов переводами. Удобно прогнать
   `node tools/check-numbers.mjs --state <файл-состояния> --report <отчёт>`,
   если отчёт уже собран, или проделать те же шаги руками.
6. **Если нашёл расхождение** — запиши его в раздел «Проверка расчётов» отчёта
   с конкретными числами. **Данные приложения не правь**: ни расходы, ни
   участники, ни переводы через скилл не создаются и не исправляются.
7. **Собери отчёт** строго по шаблону
   `.opencode/skills/trip-expense-report/templates/report-template.md` и
   требованиям `STYLE_GUIDE.md`.
8. **Проверь отчёт:** `node tools/check-style.mjs <файл-отчёта>` — он проверяет
   пять требований стайлгайда. Не прошло — исправляй **отчёт** (не данные) и
   повторяй проверку, пока не станет `5/5`.

## Если данных не хватает

Ни в коем случае не подставляй выдуманные числа. Допустимы только три варианта:

- **запроси недостающее** у пользователя (например, «не вижу расходов по этой
  поездке — пришли источник или запусти сервер»);
- **корректно остановись** и объясни, чего именно не хватает и что нужно;
- если часть данных есть, но их недостаточно для честного расчёта — не публикуй
  отчёт как «готовый», а напиши, какие строки проверить.

Признаки, что данных мало: пустой список участников; пустой список расходов;
сумма в расходе не целое число копеек; `paidById` или `participantIds` указывают
на несуществующих участников; отсутствуют балансы или переводы, хотя участники
и расходы есть.

## Условия остановки

Остановиться и не продолжать, если:

- источник недоступен и пользователь не может его указать;
- данные неполные или противоречивые, а источник исправить нельзя;
- отчёт не проходит `tools/check-style.mjs` после честных попыток — тогда
  сообщи, какое требование не выполнено;
- просят изменить данные или перевести деньги — это вне зоны скилла.

## Правила (кратко)

- **Только чтение.** Нельзя вызывать `add_expense`, `add_participant`,
  `remove_expense`, `load_demo`, `PUT/DELETE /api/...` и любые другие
  записывающие операции. Нельзя выполнять денежные переводы.
- **Только реальные данные.** Числа в отчёте берутся из источника, а не
  придумываются моделью.
- **Деньги — в целых копейках.** Все промежуточные проверки считаются в
  копейках, в рубли переводятся только при записи в отчёт (два знака после
  запятой).
- **Расхождения не «чинятся» молча.** Они пишутся в отчёт.
- **Скилл не переписывается под пример.** Один и тот же SKILL.md работает для
  любой поездки.

## Откуда брать фоновые знания

База знаний лежит в `knowledge/` и читается **по надобности**, а не целиком:

- `knowledge/INDEX.md` — индекс, с него начинай;
- справки подключай только если они нужны для текущего шага (как считаются
  доли, где какие маршруты, как устроены тесты);
- если нужной справки нет — сделай то, что понятно из кода, и запомни, что
  пришлось узнать без справки (это сигнал, что базу знаний стоит дополнить).

Если файла `knowledge/INDEX.md` нет в рабочей директории — не останавливайся:
база знаний не обязательна для работы скилла, порядок действий определяется
самим SKILL.md.
