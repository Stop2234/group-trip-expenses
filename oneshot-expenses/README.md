# Расходы группы после поездки

Веб-приложение для учёта общих расходов группы после поездки: определяет, сколько потратила группа, сколько фактически заплатил каждый, сколько расходов приходится на каждого, и кто кому должен перевести деньги для окончательного расчёта.

## Возможности

- **Участники**: добавление, список, удаление (с защитой от удаления участников, задействованных в расходах).
- **Расходы**: название, сумма (с копейками), плательщик, участники распределения, два способа деления — равное и неравное (с явными суммами долей). Добавление, просмотр, редактирование и удаление.
- **Деление расходов**:
  - равное между выбранными участниками (остаток от деления раздаётся по копейкам);
  - неравное — суммы долей задаются явно и должны строго совпадать с суммой расхода.
- **Баланс**: для каждого участника — сколько реально заплатил, сколько должен был оплатить, итоговый баланс (положительный — должны вернуть, отрицательный — должен доплатить).
- **Взаиморасчёты**: автоматический расёт переводов, закрывающих долги (жадный алгоритм, не более n−1 переводов, без нулевых переводов). После выполнения переводов балансы закрываются с точностью до копейки.
- **Итоговая статистика**: общая сумма, количество расходов, таблица по участникам, рекомендуемые переводы.
- **Демо-данные**: кнопка «Загрузить демо-данные» — 4 участника, 5 расходов, разные плательщики, деление между частью группы, неравное распределение, суммы с копейки.
- **Хранение**: данные сохраняются в localStorage браузера и переживают обновление страницы. Кнопка «Начать новую поездку» очищает данные (с подтверждением).
- **Деньги**: все суммы хранятся и рассчитываются в целых копейках — без ошибок бинарной плавающей запятой.

## Стек

- **Node.js** (>= 18) — только для локального статического сервера раздачи файлов (без внешних npm-зависимостей).
- **Чистый JavaScript (ES-модули)** — фронтенд без фреймворков и сборщиков.
- **localStorage** — хранение данных.
- **node:test** — встроенный в Node.js тестовый раннер (без дополнительных зависимостей).

Никаких npm-зависимостей, сборки и внешних сервисов нет: приложение полностью автономно.

Расчётная логика (`src/core/`) отделена от интерфейса и тестируется напрямую.

## Требования к окружению

- Node.js версии 18 или новее (проверено на Node 22).
- Любой современный браузер (Chrome, Firefox, Safari, Edge).
- npm не требуется: зависимостей нет.

## Установка

```bash
# Скопировать проект (или распаковать архив) и перейти в папку:
cd oneshot-expenses

# Устанавливать зависимости не нужно — их нет.
```

## Запуск

```bash
# Запустить приложение:
npm start

# Открыть в браузере:
# http://localhost:3000
```

Сервер также запускается напрямую: `node server.js`. Порт можно изменить переменной окружения `PORT`.

## Тестирование

```bash
# Запустить все тесты:
npm test
```

Тесты покрывают: парсинг и форматирование денег, равное и неравное распределение, деление между частью участников, плательщика вне распределения, несколько расходов с разными плательщиками, итоговые балансы, взаиморасчёты, копейки и округления, закрытие долгов переводами, валидацию некорректных данных.

## Production build

Не предусмотрен: приложение не требует сборки и транспиляции — файлы отдаются сервером как есть.

## Демо-данные

Кнопка **«Загрузить демо-данные»** в шапке страницы заполняет приложение готовым сценарием:

- 4 участника: Егор, Анна, Иван, Мария;
- 5 расходов с разными плательщиками;
- «Ужин» делится между частью группы (без Марии);
- «Экскурсия» — неравное распределение (2000 / 1200 / 1600 ₽);
- «Продукты» — сумма с копейками (2345,67 ₽), проверка округления.

Ожидаемый результат: общая сумма 26 645,67 ₽; переводы: Анна → Егор 5 661,42 ₽, Иван → Егор 722,83 ₽, Иван → Мария 838,59 ₽.

## Известные ограничения

- Данные хранятся только в localStorage конкретного браузера — между устройствами не синхронизируются.
- Валюта фиксированная — рубли; суммы вводятся в рублях с копейками.
- Редактирование участников не предусмотрено (только добавление и удаление) — имя можно изменить через удаление и повторное добавление.
- Приложение не использует серверное хранилище: весь расчёт выполняется в браузере.
