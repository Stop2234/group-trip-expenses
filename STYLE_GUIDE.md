# Стайлгайд итогового отчёта по поездке

Здесь **ровно пять** требований к оформлению отчёта. Каждое объективно
проверяемое: у него есть способ проверки одной командой.

Корректность самих денежных вычислений этим списком **не** проверяется — для
неё отдельный инструмент `tools/check-numbers.mjs`.

---

## Требование 1. Фиксированный порядок разделов

Отчёт содержит ровно эти разделы, в этом порядке и с этими заголовками:

1. `## 1. Сводка`
2. `## 2. Расходы`
3. `## 3. Балансы`
4. `## 4. Переводы`
5. `## 5. Проверка расчётов`
6. `## 6. Источник и ограничения`

Перед первым разделом идёт заголовок первого уровня `# ...` и строки
`**Источник данных:**` и `**Контрольная проверка:**`.

**Как проверить:**

```bash
node tools/check-style.mjs reports/<отчёт>.md
```

Скрипт ищет все заголовки `## N. ...` и сверяет их список с эталонным порядком.
Пропущенный, лишний, переименованный или переставленный раздел = требование не
выполнено.

---

## Требование 2. Все суммы — в рублях с двумя знаками после запятой

Каждая сумма записывается как `1 234,56 ₽`:

- разряды разделяются **обычным пробелом**;
- дробная часть отделяется **запятой** и содержит **ровно 2 цифры**;
- после числа — **один пробел** и символ `₽`;
- отрицательные суммы начинаются с `-` или `−` (минус, как в `formatMoney`);
- промежуточных чисел «просто так» в тексте быть не должно: любое число с `₽`
  обязано удовлетворять формату.

**Как проверить:** `node tools/check-style.mjs <файл>` — находит все вхождения
`₽` в файле и сверяет каждое с regex
`^[-−]?\d{1,3}(?: \d{3})*,\d{2} ₽$`. Одно нестандартное число (`3200.5`,
`1 234,5 руб.`, `6000 ₽`) = требование не выполнено.

---

## Требование 3. Расходы — таблица с фиксированными колонками

В разделе `## 2. Расходы` стоит таблица с заголовком **точно** такого вида:

```
| # | Название | Сумма | Плательщик | Участники | Доли |
```

За ним — строка разделителя, затем по одной строке на каждый расход источника.

- `Участники` — имена через `, ` в том же порядке, что в данных;
- `Доли` — суммы через ` / ` **в том же порядке, что и Участники**;
- `#` — порядковый номер с единицы.

**Как проверить:** `node tools/check-style.mjs <файл>` ищет точную строку
заголовка и разделитель, считает строки данных. Если передан файл состояния
(`--state`), дополнительно сверяется количество строк с числом расходов в
источнике.

---

## Требование 4. Балансы и переводы — две отдельные таблицы

В разделе `## 3. Балансы` — таблица с заголовком **точно**:

```
| Участник | Заплатил | Должен был | Баланс |
```

В разделе `## 4. Переводы` — таблица с заголовком **точно**:

```
| Кто | Кому | Сумма |
```

Это две разные таблицы в разных разделах; каждая содержит хотя бы одну строку
данных (если строк нет, это должно быть явно обосновано в разделе
«Проверка расчётов»).

**Как проверить:** `node tools/check-style.mjs <файл>` ищет оба заголовка,
убеждается, что они в разных разделах и что после каждого есть хотя бы одна
строка данных.

---

## Требование 5. Источник данных и результат проверки

В шапке отчёта есть ровно две обязательные строки:

```
**Источник данных:** <как получены данные: MCP / REST / файл, адрес или путь>
**Контрольная проверка:** ПРОЙДЕНА (N/N) либо НЕ ПРОЙДЕНА
```

- строка источника должна содержать конкретику: схему и адрес или путь к файлу;
- `N/N` — сколько проверок пройдено из общего числа (см. `tools/check-numbers.mjs`);
- если проверки не выполнялись — пишется `НЕ ПРОЙДЕНА` с пояснением, но не
  «ПРОЙДЕНА».

**Как проверить:** `node tools/check-style.mjs <файл>` ищет обе строки,
проверяет, что источник не пуст, а после `**Контрольная проверка:**` идёт
допустимое значение.

---

## Как читать результаты проверки

```bash
node tools/check-style.mjs reports/<отчёт>.md
```

Вывод: по одной строке на требование (`PASS` / `FAIL`), итог `5/5` и код
завершения `0` только когда прошли все пять. `FAIL` всегда сопровождается
тем, что именно не так.

Проверка оформления **не** заменяет проверку арифметики:

```bash
node tools/check-numbers.mjs --state data/<состояние>.json --report reports/<отчёт>.md
```
